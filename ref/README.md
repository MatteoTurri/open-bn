# ref/ — the third-party code linked into `bn`

`src/` is the Sony code decompiled from scratch; `ref/` holds the libraries that `bn` links and
that exist (or existed) as source outside Sony: each tree is the upstream release the binary was
built from, with the changes needed to reproduce the binary. Every change below was read off the
original code or data; none is a tuning of the compiler output.

How to read this file:

- **Upstream** is the release and where its source comes from (the sha256 is that of the archive
  that was compared with the tree).
- **Build**: the units and their flags are rows of `config/units.txt` (the base command is `-O2`;
  a later `-O` in the row overrides it). Asflags `-g2` mean gas runs with `mips_optimize=1`: it
  does not move instructions into branch delay slots, so the `nop`s gcc left stay where they are.
  Some units are compiled with the path the original build used, so that `__FILE__` (assert and
  error messages) is the same string: `config/unit_paths.txt`.
- **Deviations** come from a `diff -r` of the tree against the upstream archive; files only used
  to build the tree (configure output, generated sources) are listed apart.
- A comment in a vendored file may not change the number of lines: `__LINE__` and `#line` reach the
  binary through the asserts.

The libraries are listed in alphabetical order of their directory.

## gcc-2.95.2 — pieces of libgcc and crtstuff

- **Upstream**: gcc 2.95.2, `docker/sonygcc/gcc-2.95.2.tar.gz` (the tarball the toolchain is built
  from; sha256 `064e1cb06ea5d2f4a07ec46c1c64d771f74d04f404b6a6766bca2477f7d72482`).
- **Build**: `crtstuff.c` and `crtstuff_end.c` are units of their own (no flags). `libgcc2.c` and
  `fp-bit.c` are not units: the `src/lib/` units define one `L_<section>` and include them, as the
  libgcc build does (`L_moddi3` at `-g` with asflags `-g2`, `L_floatdisf`, `L_df_to_si`,
  `L_df_to_usi`, `L_si_to_df`), with `-Iref/gcc-2.95.2`.
- **Same as upstream**: `libgcc2.c`, `longlong.h`, `fp-bit.c` (from `gcc/config/fp-bit.c`). They are
  the vanilla files: the Sony patch of `libgcc2.c` (applied in the toolchain build) only has
  hunks after the sections compiled here.
- **Deviations**:
  - `crtstuff.c` / `crtstuff_end.c`: only the functions that are in the binary, rebuilt from it
    (the crtbegin half: `call_gmon_start`, `__do_global_dtors_aux`, `fini_dummy`, `frame_dummy`,
    `init_dummy`; the crtend half: `__do_global_ctors_aux`, `init_dummy`). Upstream is one file
    compiled twice (`-DCRT_BEGIN`, `-DCRT_END`); here it is two files because each unit is one
    source. The section switches keep the upstream mechanism (an `asm` that moves the call into
    `.init`/`.fini`), written as string literals instead of the target macros.
  - `call_gmon_start` keeps the address of the weak `__gmon_start__` in a local before calling it
    (the binary calls through the register, it does not reload the GOT slot).
  - `defaults.h`, `machmode.h`: empty placeholders; the compiled sections need nothing from them.
  - `tconfig.h`: generated by the gcc build, written here with the four target macros libgcc2.c
    reads (`WORDS_BIG_ENDIAN 0`, `BITS_PER_UNIT 8`, `LONG_DOUBLE_TYPE_SIZE 64`, `SUPPORTS_WEAK 0`).

## giflib-4.1.0 — GIF reader and writer

- **Upstream**: giflib 4.1.0 (Toshio Kuratomi, 1999), the release with the LZW encoder (not
  libungif); archive.org item `tucows_9274_Giflib`, `giflib-4.1.0.tar.gz` (sha256
  `d6991d5335037756ed80ffed29c6c57f79b0edfd766c1d539bd7bfa081892a5f`); the tree holds the `lib/` files.
- **Build**: `dgif_lib.c`, `egif_lib.c`, `gif_err.c`, `gifalloc.c`, `quantize.c` at `-O0 -g`, asflags
  `-g2`. `gif_hash.c` is not built: none of its functions is in the binary.
- **Deviations** (the library in `bn` is a fork of a revision close to 4.1.0):
  - `gif_lib_private.h`: `Prefix[LZ_MAX_CODE]`, not `+1` — the binary allocates 24,900 bytes, not
    24,904, for the private state.
  - `egif_lib.c`: the encoder has no hash table. `EGifOpenFileHandle` does not call
    `_InitHashTable`, `EGifCloseFile` does not free it, `EGifSetupCompress` starts `RunningCode`
    at 0, `EGifCompressLine` emits every pixel as a literal code and sends a ClearCode when
    `RunningCode` reaches `(1 << BitsPerPixel) - 2`, and `EGifCompressOutput` has no block that
    raises `RunningBits` — the five static encoder functions of the binary call nothing else.
  - `egif_lib.c`: in `EGifCompressLine` the now unused locals stay, with `Private` declared before
    `HashTable`: at `-O0` they fix the frame (80 bytes) and the stack slots of the original.
  - `dgif_lib.c`: `DGifGetImageDesc` copies the colour map contents into `SavedImages` (`memcpy`
    of the pointers' targets, sized by `ColorCount`), where 4.1.0 copies the pointer's bytes.
  - `dgif_lib.c`: `DGifCloseFile` frees the image colour map only `&& !GifFile->SavedImages`
    (after `DGifSlurp` it belongs to the saved images).
  - `dgif_lib.c`: in `DGifSlurp` the `AddExtensionBlock` call is written `ExtData + 1` on one line
    and its comment lines are gone (same expression).

## jpeg-6b — IJG libjpeg 6b

- **Upstream**: `jpegsrc.v6b.tar.gz` from https://ijg.org/files/ (sha256 `75c3ec241e9996504fe02a9ed4d12f16b74ade713972f3db9e65ce95cd27e35d`).
  Version from the exported symbols (`jpeg_simple_progression`, `jpeg_new_colormap`,
  `jpeg_save_markers`: 6b, not 6 or 6a); the binary has no version string.
- **Build**: 42 units at the base `-O2` (not `-O3`: `jpeg_set_quality` must call
  `jpeg_quality_scaling`, not inline it), no asflags. Memory back end `jmemnobs.c`.
- **Generated**: `jconfig.h`, the standard "Unix ANSI C" configuration of `jconfig.doc`
  (`HAVE_PROTOTYPES`, `HAVE_UNSIGNED_CHAR`, `HAVE_UNSIGNED_SHORT`, `HAVE_STDDEF_H`,
  `HAVE_STDLIB_H`).
- **Deviations** (Sony's error handling is cut down):
  - `jerror.h`: `TRACEMS`, `TRACEMS1..5`, `TRACEMS8`, `TRACEMSS` are `((void) 0)` — no trace call is
    in the binary (`ERREXIT*` and `WARNMS*` stay).
  - `jerror.c`: `JMESSAGE` is empty, so `jpeg_std_message_table` is a single `NULL` (4 bytes in
    `.dynsym`) and none of the message texts is in the binary.
  - `jerror.c`: `error_exit` only calls `jpeg_abort` and returns (no message, no `exit()`);
    `format_message` prints `"Error! code =(%d)\n"` with the message code.
  - `jcsample.c`: `jinit_downsampler` has no `smoothok` variable and no trace of the unsupported
    smoothing case (`INPUT_SMOOTHING_SUPPORTED` stays defined).
  - `jdmarker.c`: `first_marker` returns `FALSE` after the `ERREXIT2` of a missing SOI, because
    the fork's `error_exit` returns.

## libps2dev-1.0 — Sony's PS2 Linux device libraries (LGPL)

- **Upstream**: `libps2dev-1.0.tar.gz` inside the source RPM `SRPMS/LIBPS2_1.RPM` of the PS2 Linux
  Kit disc 2 (sha256 of the tarball `da12b8ce572e8bef1216edd8ffacdd81bda5f5381ffffe86ba86e318ed949310`). Its Makefile builds with
  `-O2 -g -DDEBUG -Wall -fno-common`.
- **Build**: 13 units with `-DDEBUG -fno-common`; `-g` on `memlib.c`, `gs_open.c`, `vpu_file.c`,
  asflags `-g2` on `gs_open.c` and `vpu_file.c`.
- **Deviations** (the binary links a revision different from the kit's 1.0):
  - `ps2gs/gs_reset.c`: the second `switch (omode)` covers only NTSC and PAL, not DTV.
  - `ps2gs/gs_reset.c`: DTV 1080I does not count as interlaced.
  - `ps2gs/gs_reset.c`: `PS2_GS_720P` is 1280x720, not 1024x720.
  - `ps2gs/gs_reset.c`: in the CRT mode switch DTV has a branch of its own,
    `crtmode.res = gp->resolution`.
  - `ps2mem/memlib.c`: both `mmap()` calls on `/dev/ps2mem` use `MAP_SHARED`, not `MAP_PRIVATE`
    (`li a3,1` in `ps2mem_alloc_pages`).
  - `ps2vpu/ps2vpu.c`: an explicit `nop` at the end of the `asm` blocks of `ps2_vpu_start` (both
    branches, and `;` after `vcallmsr vi27`) and of `ps2_vpu_busy`: after the `ctc2`/`cfc2`
    transfer the original has a `nop` before returning, so the return delay slot is not filled
    with the last instruction of the block.

## rcom-1.1.0 — RSA's RCOM 1.1.0 (BSAFE crypto engine and common services)

- **Upstream**: none public. RCOM 1.1.0 is the crypto component of RSA Security's SSL-C 2.1.0
  (`"Big Number part of RCOM 1.1.0 30-Jan-2002"` in `bn_lib.c`, banners in `.rodata`); see
  `ref/sslc-2.1.0/README.md`. This tree is a reconstruction from the binary: RSA's own code
  (BSAFE style: `B_*`, `KIT_*`, `ALG_*`, `AI_*`/`AM_*` tables, `CMP_*` arithmetic, ASN/BER/DER,
  `R_*` services, `PK_*`/`OP_*` key operations) and the SSLeay-derived big-number code.
- **Build**: the SSLeay-derived part (`bn_*`, `pk_*`, `op_*`, `r_*`, `ber_*`, `rsa_*`,
  `time_mi*`, `cert*`, ...) at `-O0 -g`; the BSAFE engine (`bsafe_*`, `cmp_*`, `kit_*`, `rc6_*`,
  `ah*`, `alg*`, `a_*`, `asn*`) at the base `-O2 -g`; asflags `-g2` on all units but one.
  Includes: `-Iref/rcom-1.1.0` plus the SSL-C headers.
- **What differs from SSLeay 0.9.0b** in the big-number code (the `BIGNUM` structure is in
  `ref/sslc-2.1.0/crypto/bn/bn.h`):
  - it is the BN of a later OpenSSL: `BN_mod_inverse(in, a, n, ctx)` with four arguments,
    `BN_mul(r, a, b, ctx)`, and the word-level kernels `bn_mul_normal`, `bn_mul_comba8`,
    `bn_sqr_normal`, `bn_sqr_comba8`, called directly by `BN_mod_mul_montgomery`;
  - `BIGNUM` has the `flags` field of later OpenSSL (`BN_FLG_MALLOCED`, `BN_FLG_STATIC_DATA`,
    `BN_FLG_FREE`);
  - the error reporting is gone: SSLeay 0.9.0b has 17 `BNerr` calls in `crypto/bn`, the RCOM
    sources none (the binary has no such call);
  - allocation goes through `R_malloc`/`R_free`, randomness through the RCOM generator
    (`BN_rand` takes the generator context and calls `R_rand_bytes`).

## small-fmt6 — the Small (Pawn) abstract machine, file format 6

- **Upstream**: Small 2.73 of ITB CompuPhase (`smallkit-273.zip`, 2005-02-09, from
  `compuphase.com/pawn/` via web.archive.org, sha256 `74f0c2e7af82c92921708ff47b2d1f6d018251dbee7b587865bec2da1bb714de`), files `AMX/amx.c`,
  `AMX/amx.h`, `AMX/osdefs.h`, `AMX/amxcore.c`, `AMX/amxcons.c`. The binary links an earlier
  revision, file format 6, that is not published.
- **Build**: `amx.c` with `-DSN_TARGET_PS2 -DNDEBUG -finline-functions -DAMX_COMPACTMARGIN=32`;
  `amx_strpack.cpp` and `amxcons.cpp` as C++ with `-DSN_TARGET_PS2 -fno-exceptions` (plus
  `-DNDEBUG` on `amx_strpack.cpp`), because the native modules include the script host headers.
- **Same as upstream**: `osdefs.h`.
- **Deviations**:
  - `amx.c` is 2.73 patched back to the revision in the binary; the note at the top of the file
    lists every change: file format 6 (`CUR_FILE_VERSION 6`, `MIN_FILE_VERSION 4`) with a one-time
    migration of format-5 headers in `amx_Init`, table counts by division of adjacent offsets
    (one `AMX_FUNCSTUB` size), the runtime `amx_LittleEndian`, an older GNU interpreter in
    `amx_Exec` (135-entry opcode list, no `SYSREQ.D`, label table keyed on `amx == NULL`), and no
    `amx_Cleanup`, `amx_Clone`, `amx_MemInfo`, `amx_GetNative`, `amx_FindNative`, `amx_UTF8*`.
  - `amx.h`: format 6, no `sysreq_d` in `AMX`, `AMX_FLAG_CHAR16` still defined, the older
    `amx_GetString`/`amx_SetString` (no `use_wchar`), no `amx_NumNatives` prototype, and the
    structure tags `__amx`/`__amx_header` (the names in the C++ mangled symbols of `bn`).
  - `amx_strpack.cpp`: the module `smallext_core`, a cut-down `amxcore.c`: `amx_StrPack`,
    `amx_StrUnpack` and the natives `numargs` .. `clamp` in the upstream order, without `funcidx`
    and the property natives; the packed test is `> UCHAR_MAX` instead of `UNPACKEDMAX`.
  - `amxcons.cpp`: the module `smallext_cons`, only `getstring` and `printf`, both `return 0`.

  `os.c`), asflags `-g2`, with `-Iref/sqlite-2.7.2/gen -Iref/sqlite-2.7.2/src`. The `src/` units
  are compiled as `./src/<file>.c`, the path of the original build (`config/unit_paths.txt`).

    to the level of the switch body, which changes which stack temporaries are still in use when
    the `#ifndef NDEBUG` trace block allocates `zBuf[100]` (frame of 1,424 bytes, `zBuf` at
    `sp+1024` as in the original). Each removed brace is replaced by a comment line: the file must
    keep 5,322 lines (an `assert` at line 5280 compiles `li a2,5280`).

## sslc-2.1.0 — RSA's SSL-C 2.1.0

- **Upstream**: none public; see `ref/sslc-2.1.0/README.md`. In short: RSA Security's commercial
