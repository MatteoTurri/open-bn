# Linking (`make link`, `make link-cmp`)

`make link` links the objects of the last full `make check` into `build/relink/bn.elf` with Sony's
ld 2.9EE; `make link-cmp` compares it with `orig/bn-jpn.elf` section by section and by SHA1. The two
SHA1s are identical. What the link takes from the original instead of building it is listed in
`docs/original-bytes.md`; tool usage is in `tools/README.md`.

```sh
make check        # full: the link reads build/check.json, datacheck.json, ehcheck.json
make link         # -> build/relink/bn.elf
make link-cmp     # exit 0 identical SHA1, 1 different (sections listed), 2 comparison broken
```

## Pipeline

`tools/relink/fetch.py` runs on the host (it needs the network); everything else runs in the
container through `make link-in`. Outputs go to `build/relink/`, downloads to `build/relink/dl/`; none
of it is tracked. Every path and binary comes from `tools/relink/paths.py`.

1. **fetch.py**: third-party files, each pinned by SHA1. `crtbegin.o`, `crtend.o` and `libgcc.a` from
   `GCC-29_1.RPM` of the PS2 Linux Kit disc 2 (`/SCEI/RPMS/`; the disc is downloaded by
   `tools/fetch_kit.py` if missing), and the PSBBN Definitive Patch v4.1.0 tarball from archive.org
   (PSBBN's libc, `ld.so`, libstdc++, libocm, and the reference libfreetype).
2. **layoutcheck.py**, only if `build/layoutcheck.json` is older than `build/check.json`: the
   original `.text` base of every object (below).
3. **make_libs.py**: `build/relink/libs/`, the shared libraries the link resolves against (below),
   including a generated libfreetype stub.
4. **link_order.py**: the order of the objects, from the original addresses of their `.text`;
   data-only units go after the unit with the preceding data block. The same order is consistent with
   every other section. Gaps between the expected end of an object and the next one are pieces no
   object provides (blobs).
5. **make_blobs.py**: the blobs cut from the user's ELF (Chloe, ATOK tables, DNAS tables in `.text`).
   A blob that does not start or end on 16 bytes shares a section with a neighbouring unit, whose
   object is rebuilt from its gate `.s` with the bytes included at the head or the tail.
6. **link.sh**:
   - `missing_syms.py`: symbols used by our objects that nothing defines. Only the five generated by
     the linker are allowed (`__gmon_start__`, `__start/__stop___vpu_symtab`,
     `__start/__stop___dmamem_symtab`); anything else fails the link;
   - `partial_r.py` and `ld -r` of the group of `config/relink_partial_r.txt` (below);
   - `ld -E -T config/bn.x`, libraries in the order of the original's `DT_NEEDED`;
   - `mipsEEel-linux-strip` 2.9EE without options;
   - `dnas_protect.py`: DNAS descriptors and re-encryption of the 166 regions (`docs/dnas.md`);
   - `compact_rel.py`: `relvaddr` and `cpt.offset` of `.compact_rel` copied from the original
     (`docs/original-bytes.md`, item 1).

Intermediate images: `bn.unstripped.elf` (with `.mdebug`, `.symtab`, and the map `bn.map`),
`bn.stripped.elf`, `bn.protected.elf`. `link.sh` deletes them first, so a failed run leaves no stale
output. The link fails if a gate object is newer than `build/check.json` or `build/layoutcheck.json`,
or changes during the run (SHA1s in `build/relink/inputs.sha1`): `tools/match` and a concurrent
`make check` rewrite `build/check/`. `RELINK_ALLOW_STALE=1` and `RELINK_ALLOW_MISSING=1` let it run
anyway, for measuring only.

`tools/relink/cmp.py` reports per section: addresses, sizes, equal bytes, first difference; for code,
the original function holding it and how many differing bytes fall in the DNAS regions. `--mask-gp`
separates differences caused by a different GOT order from real ones.

## The libraries

ld copies into the executable's `.dynsym` the size of each imported symbol from the first library
(in `DT_NEEDED` order) that defines it, so the sizes in the original `.dynsym` say which build of each
library Sony linked against.

| library | file used | evidence |
|---|---|---|
| `libc.so.6` | PSBBN's (Definitive Patch, `__linux.1/lib`) | `__register_frame_info` 184 B and `__deregister_frame_info` 296 B, as in the original (the kit's: 68/156) |
| `libpthread.so.0` | the kit's (glibc 2.2.2) | 64/64 sizes equal; PSBBN's differs on `pthread_join`/`exit`/`detach` |
| `libm`, `libdl`, `libcrypt` | the kit's (glibc 2.2.2) | the glibc 2.2.2 build of libpthread |
| `libstdc++-libc6.2-2.so.3` | PSBBN's (`__linux.1/usr/lib`) | 36/36 sizes equal (the kit's: 29/36) |
| `libocm.so` | OpenMG, Definitive Patch `__linux.4/bn/openmg/libocm.so.1.3` | needed only as `DT_NEEDED`; it has no `DT_SONAME`, so it must be copied as `libs/libocm.so` and the name comes from `-locm` |
| `libfreetype.so.6` | a stub generated from the original | the Definitive Patch build has 4/10 sizes equal: Sony used another build of FreeType 2 |

`malloc`, `free`, `realloc` and `calloc` have size 0 in libc (weak aliases); the sizes in the original
(404, 52, 192, 100) come from the weak definitions of `ld.so.1` (`dl-minimal.c`), which ld reads while
resolving libc's dependencies through `-rpath-link`. The same four sizes are in `bn_asap`, another Sony
executable linked in the same environment.

`libc.so` is replaced by a script `GROUP ( libc.so.6 )` without `libc_nonshared.a`: `stat` and `lstat`
are units of our own (`src/lib/libc_stat.c`, `libc_lstat.c`). The crt files are the kit's `crt1.o`,
`crti.o`, `crtn.o` and the `crtbegin.o`/`crtend.o` of `GCC-29_1.RPM`; `ref/gcc-2.95.2/crtstuff.c` also
provides the `.text` of crti (`call_gmon_start`).

## What the linker decides, and how the source follows it

**ld 2.9EE.** `mipsEEel-linux-ld` is GNU ld 2.9-ee-990721, built by `make sony-binutils` from the same
tree and configuration as gas. Two traps:
- ld 2.9 has no `-nostdlib` (that is a gcc driver option): `getopt_long_only` reads it as `-n -o
  stdlib`, and `-n` turns off paging;
- the cross linker has no sysroot, and the kit's `libc.so` is a script with absolute paths: pass the
  files, or a rewritten `libc.so`, with `-L`/`-rpath-link` to the kit libraries.

**Linker script.** `config/bn.x` is ld's built-in script with every allocated output section started
at the original address (a difference stays inside its section instead of cascading), `.rel.dyn`,
`.rld_map` and `.note.ABI-tag` placed as in the original, and `_gp = 0x100d9910`. There is no `PHDRS`:
the original is `strip(link)`, not `ld -s`, and only the strip reproduces the 7 program headers with
`PHDR p_filesz 0xe0`.

**`.fini`.** The original has 24 zero bytes in `.fini` between crtbegin and crtn: the signature of an
input made with `ld -r` (the `-r` script closes `.fini` with `QUAD(0)` x3). `config/relink_partial_r.txt`
lists the objects merged that way, which must be contiguous in the link order. Which group it was is
not known (the Chloe files are used); for the bytes it makes no difference.

**`.mdebug` and `.compact_rel`.** ld creates `.compact_rel` in the dynamic object, `crt1.o`, after its
sections. The kit's `crt1.o` is linked as is, with its `.mdebug`, so that the two non-allocated orphans
come out in the original's order (`.mdebug` then `.compact_rel`, section symbols 24 and 25 of
`.dynsym`). Every path that gas sees ends up in `.mdebug`, hence in `cpt.offset` before it is
replaced: all paths of the pipeline are relative to the root and fixed.

**Exported symbols.** `-E` exports every defined global: the original `.dynsym` has 9,694 entries.

**`.dynsym` and GOT order.** ld walks its internal symbol hash table (bfd's default size, 4,051
buckets): globals come out in bucket order, and inside a bucket the last inserted first. The global
part of the GOT repeats `.dynsym` from `DT_MIPS_GOTSYM`. Hence the order of definitions and the set of
global names decide the GOT offsets of every function.

**`local_gotno`** (137 in the original) depends only on the total size of the allocated input
sections (`elf32-mips.c`): shared libraries do not count, `COMMON` symbols do not, and **linkonce
copies discarded by the linker do**. An inline function of a header that is never called still makes
every unit that includes the header emit the template copies it calls; the linker discards them, but
they count. So the headers a unit includes, and the inline bodies in them, reach the binary through
`local_gotno` even where the code does not change (`docs/compiler.md`, headers).

**Linkonce sections.** For each `.gnu.linkonce.t.<name>` ld keeps the first section in link order and
places the kept ones at the end of `.text`, after `crtstuff_end`, in blocks per object in the order of
each `.s`. The `.dynsym` size of such a symbol is that of the last copy seen (`bfd/elflink.h`): this is
why `src/gfx/bmp.cpp` and `src/app/database.cpp` are compiled at `-O3`, whose copies (`_M_insert_aux`, ...) carry
the sizes of the original. For a symbol defined by a shared object and by the
link (`_gp_disp`, `_procedure_table_size` of libfreetype), ld writes into the GOT the first definition,
which is why the stub carries the real library's values.

## Layout (`tools/layoutcheck.py`)

The function gate places each function alone; `tools/layoutcheck.py` checks that each object, laid by
the linker at one base, reproduces the original addresses: no body without an address, no function
credited to another unit, a constant offset between consecutive functions, no original function of the
unit's range missing, and a base that is a multiple of 16 (every gas 2.9EE object starts 16-aligned, so
a function at 8 mod 16 right after another one is in the same object). All units pass. With
`LAYOUT_OVERLAP=1` it also walks every section in link order and reports overlaps and holes between
units. It is a measurement and changes no exit code; the link SHA1 is the judge.

## Variants (`VARIANT=<name>`)

`config/variants.txt` lists builds that differ from the original only in some bytes, each with the
SHA1 of the `bn.elf` it must produce. `make link VARIANT=<name>` recompiles the variant's units with
their extra flags (`tools/relink/variant.py`, same compile as the gate) and links them in place of the
gate's objects; `make link-cmp VARIANT=<name>` compares with the variant's SHA1. A variant must not
change any section size: the steps that take parameters from the original (DNAS protection,
`.compact_rel`) assume its layout, and `variant.py` rejects a unit whose sizes differ.

```sh
make link VARIANT=definitive && make link-cmp VARIANT=definitive
```

`definitive` is the `bn` installed by the PSBBN Definitive Patch: the original with three soft-key
labels in English (`src/app/gettext.cpp`, `DEFINITIVE_PATCH`).

Variants only make sense while the sources still reproduce the original layout: they pin the
releases of the matching tree. Once the program changes, its builds are checked on the console,
not by SHA1.

## Environment notes

- After a pull that touches `docker/patches/` or the Dockerfiles, rebuild with `make sony-gcc` (or
  `make sony-binutils`) and check the timestamps of the binaries in `docker/toolchain/`, not the exit
  code.
- The container runs as the host user (`--user $(id -u):$(id -g)`, `HOME=/tmp`). A checkout used as
  root before needs one `sudo chown -R "$USER" build docker/toolchain`.
- On Apple Silicon the i386 compiler runs under Docker Desktop's `qemu-i386`; `tools/fixtime.py` uses
  `PTRACE_GET_SYSCALL_INFO` and works there. If it cannot run on a host, `-D__DATE__=... -D__TIME__=...`
  gives the same `.s` (with a different command line and two warnings).
- archive.org's server-side unzip truncates at about 1 GiB: `tools/fetch_kit.py` reads the central
  directory of the kit zip and downloads only the disc-2 member with an HTTP range.
- `make link-cmp` exits 1 for a different SHA1 and 2 for a broken comparison or a missing file; make
  reports both as a failed recipe, with the code in its message.
